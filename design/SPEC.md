# 见文 / Essay Lens

Design reference: concept.png, generated using the built-in imagegen tool. Full primary desktop workspace. White background #fff, text #212b29, green #245b46, rules #e5e9e5. Editorial sans serif Chinese typography, restrained native controls, no photos/gradients/shadows. Header and footer rules; a single vertical divider separates an editor and result region. Header 72 px; page width 1320 px; 56 px desktop gutters; heading 46 px, section headings 25 px, body 15 px. Corners 4 px. Controls 44 px minimum. Mobile stacks editor and results; no horizontal scrolling. No imagery is required in production: the chart is accessible data-driven SVG.

Visible copy matches the concept: 见文 / ESSAY LENS; 评价工作台 / 评分标准; 让你的故事，被更清楚地看见。; 六个维度，读懂一篇文书。基于 Jev 的个人文书评价。; 你的文书; 导入 TXT; 在这里粘贴英文个人文书…; 清空; 开始评价; 查看示例; 六维画像; 导出报告; 评价写作，不预测录取。六维等权，十档标准。

Functional necessities extending the single concept: real consent/privacy link, error/loading/empty states, stale-result notice, current model and rubric version, keyboard-accessible dimension selection, probability distribution and exact rubric below the fold, report export and local-print support. The initial state shows an empty chart rather than fabricated scores; 查看示例 explicitly activates synthetic UI data. Sample total calculated from sample dimensions is 82.4 rounded. No private essays or previous user results will be bundled. Fixed six dimensions and all 60 criteria copied unchanged from the user's referenced neutral evaluation. The editor accepts English undergraduate personal essays; school-specific prompt matching and other essay genres are outside v1.

Components: App (composition + request state), EssayEditor (input/import/consent), EvaluationReport (result controls + metric list), Radar (SVG), RubricPanel (full standard), report utilities. Loading reflects a real pending request, no invented progress percentage. Server keeps key private, sends exact essay and fixed questions, validates all six returned answers, never logs/stores essay text. In-memory usage limits are abuse controls, not a durable billing cap.
